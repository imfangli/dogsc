# 备忘录语音跟读

需要 macOS 26 或更高版本，以及支持 `SpeechTranscriber` 的 Mac。应用仍支持 macOS 14；较旧系统继续使用手动备忘录。

## 使用

1. 在录制条中打开备忘录，写下或粘贴文稿。
2. 开启 **语音跟读**，备忘录自动进入阅读模式。首次使用时允许麦克风访问；普通话模型缺失时先点击下载。
3. 看到 **正在聆听** 后开始朗读。可靠定位后会高亮当前句，并将朗读位置滚动到窗口约三分之一处。
4. 可以从中间开始、跳到前文或后文、重复朗读。重复短句和离稿讲话时保持位置，等待足够上下文。
5. 需要人工指定位置时，在阅读模式选中稿件，再点 **从选中位置跟读**。手动滚动不会关闭跟读，手势结束后的下一次可靠定位会继续跟随。

练习时使用当前选择、上次选择或系统默认麦克风；录制中共用录制麦克风。**录制麦克风声音**控制项目音轨，**语音跟读**控制实时监听，两者独立。关闭麦克风音轨或暂停录制时仍可提词。

切换编辑模式、隐藏备忘录或退出应用会停止监听，重新打开默认关闭。文稿、字号和透明度继续自动保存在本机。麦克风权限拒绝、设备断开或识别失败时，文稿位置保留，可检查设备后重试。

## 本机处理

识别使用苹果 `SpeechAnalyzer` / `SpeechTranscriber` 普通话模型，稿件中的英文术语提供识别上下文。模型下载使用系统资源管理；识别不回退到云端，不使用旧 `SFSpeechRecognizer` 授权流程。

识别支路复制原始 PCM 并按引擎格式重采样，不改变录音写入的采样率或时间戳。识别音频和识别文本只在有界内存队列中处理，不额外写入文件。开启跟读不会启用项目的麦克风音轨。

## 开发验证

构建需要 Xcode 26 或更高版本提供的 macOS 26+ SDK，部署目标仍为 macOS 14。窗口布局和定位测试不请求麦克风权限。

```sh
swift test
```

测试涵盖全文定位、前后跳读、重复句歧义、数字与英文、UTF-16 范围、临时结果修订、迟到结果、密集批次合并和限频重试。音频测试覆盖独立 PCM 复制，以及 44.1/48 kHz 短音频块重采样后的时间轴；窗口测试覆盖长稿缩窗、高亮与撤销、手动滚动后恢复跟随。定位性能测试使用两万字稿件。

可使用一段本地普通话测试音频运行实际苹果引擎测试；这条测试使用合成稿件，不请求麦克风，也不下载模型：

```sh
DOGSC_SPEECH_TEST_AUDIO=/absolute/path/to/mandarin-test.aiff swift test \
  --filter MemoSpeechAudioTests.testInstalledAppleSpeechWithSyntheticAudio
```

引擎测试以 512 帧的短块发送音频，并检查完整识别过程没有报错。可使用 48 kHz 音频覆盖常见麦克风的转换比例；音频应朗读以下测试文稿：

> 先把需要介绍的内容粘贴到备忘录里面，然后打开语音跟读开关。接下来可以从文稿中间开始朗读，软件会自动找到对应的句子。最后检查录制画面和麦克风声音，确认已经做好准备工作。

引擎测试要求 macOS 26、支持的硬件和已安装的普通话模型；普通 `swift test` 会跳过此项。实际发布前还应在目标设备检查麦克风切换、拔插、练习转录制、暂停、手动滚动和屏幕录制中的辅助窗口排除。
